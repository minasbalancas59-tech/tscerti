 CORRIGE "CPF DO REPRESENTANTE FALTANDO" JÁ PREENCHIDO
 10/09/2026
════════════════════════════════════════════════════════════════

O PROBLEMA (visto na CALTECH, CNPJ 32.759.589/0001-00)
─────────────────────────────────────────────────────
A tela mostrava o CPF certinho no campo, mas ao tentar gerar o
contrato o aviso dizia "dados faltando: CPF do representante".

CAUSA
─────
A função que gera o contrato reaproveitava um CACHE (window.
_saDadosContrato) preenchido só uma vez, quando a tela de edição
abre. Se você editasse e salvasse o CPF (ou qualquer outro dado do
contrato) sem RECARREGAR A PÁGINA, esse cache ficava com o retrato
ANTIGO — a validação lia dali, não do que tinha acabado de ser
salvo, e acusava "faltando" um campo que já estava no banco.

O QUE MUDA
──────────
Agora busca sempre os dados frescos do servidor antes de validar.
Um arquivo só: src/Api/wwwroot/app.js.
Testado contra um clone limpo do GitHub antes do envio.


COMANDOS
────────
    cd /root/cert-saas
    unzip -o fix-cpf-cache.zip
    git apply --check fix-cpf-cache.patch
    git apply fix-cpf-cache.patch
    git add -A
    git commit -m "Corrige contrato acusando CPF do representante faltando ja preenchido"
    git push
    ./atualizar.sh --build
    rm -f fix-cpf-cache.zip

Não há migration.


COMO CONFERIR
─────────────
Na CALTECH (ou qualquer empresa), gere o contrato de novo — o
aviso de dados faltando não deve mais aparecer, já que o CPF está
salvo. Também vale testar o caso que causava o bug: edite um campo
do contrato, salve, e SEM recarregar a página, gere o contrato na
sequência — não deve mais dar falso alarme.
